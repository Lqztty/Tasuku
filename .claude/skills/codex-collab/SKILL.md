# Codex連携スキル

Codex CLIを「賛成役」ではなく**批判的レビュアー**として使うための運用ルール。
メインエージェント（Claude）が主担当、Codexは独立したセカンドオピニオン提供者。

## 依頼トリガー（起動判断）

以下に**1つでも該当**したらCodexを起動する。迷ったら起動する方が安全。

| トリガー | 具体例 |
|----------|--------|
| **設計の非自明性** | レイヤー配置、DDD境界判断、新ドメイン追加 |
| **2回以上失敗したバグ** | 同じ仮説で2回直して再発 → 視点転換が必要 |
| **広い差分** | 3ファイル超のクロスレイヤー変更、migration、リファクタ |
| **破壊的/不可逆変更** | DBスキーマ、APIコントラクト、auth/permission |
| **セキュリティ/性能/データ整合性** | SQLインジェクション可否、N+1、トランザクション境界 |
| **サブエージェント結果の妥当性確認** | 返却コードが「もっともらしい」が確信が持てない時 |
| **高インパクトPR直前** | ユーザー向け動作変更を含む最終確認 |

**起動しない**:
- 単一ファイル/局所リネーム
- 明らかに正解が1つのCRUD追加
- UI微調整（色、余白等）

## 依頼テンプレート

Codexに渡すプロンプトは**構造化する**。賛成意見ではなく反対意見を引き出す。

```
## 文脈
- プロジェクト: {プロジェクト名} (Laravel 12 + React 18 + Inertia 2.0, DDD 3層)
- 対象: {機能名/ファイルパス}
- 変更概要: {1-3行}

## 現在の方針
{採用しようとしている案を簡潔に}

## 依頼内容（以下を必ず答えてほしい）
1. この方針の回帰リスク/見落としは？
2. より単純な代替案はあるか？
3. 不足しているテスト/検証は？
4. 同意できない点があれば指摘してほしい

## 参考ファイル
{重要なファイルパスと、該当する行番号}
```

### 呼び出し例（3モード）

```bash
# 1. 差分レビュー（PR前）
codex review --base main --head HEAD

# 2. チャレンジ（破壊しにくる）
codex challenge "この認証フローを破る攻撃ベクトルを3つ挙げて"

# 3. コンサル（セッション継続）
codex consult "DDDでNotification機能を追加する時、Domain層に何を置く？"
```

## 結果の取り扱い（必須）

Codex回答は**必ずメインが再評価**する。盲目転記禁止。

| Codex指摘 | メイン対応 |
|-----------|-----------|
| CRITICAL/データ損失系 | **即修正**。修正案もCodexに投げて検証 |
| パフォーマンス懸念 | 計測してから判断。根拠なく最適化しない |
| 「より単純な案」の提示 | 既存プロジェクト規約(DDD/Atomic)と整合するか確認 |
| スタイル/好みの違い | 本プロジェクト規約(`.claude/rules/`)を優先 |
| 誤解・事実誤認 | 追加コンテキストを渡して再依頼（1回まで） |

**Codexが「問題なし」と言っても最終判断はメインの責任**。

## この構成で必ず確認する観点

Codex依頼時に**必ず含めて確認を求める**項目:

1. **DDD 3層の責務ずれ**
   - Controller内ビジネスロジック混入
   - UseCase内Eloquent直接使用
   - Domain層のフレームワーク依存
2. **既存コンポーネント重複**
   - `src/resources/js/Components/` の再利用漏れ
   - features/内の共通化候補
3. **命名/ユビキタス言語ズレ**
   - 対象ドメインの `CLAUDE.md`・用語集との不一致
   - deprecated用語の混入
4. **Docker前提崩し**
   - ホストでのコマンド実行前提になっていないか
5. **ダーク/ライト両対応**
   - `dark:` バリアント欠落

## ワークフロー統合

```
実装着手
  ↓
[小規模判定] → YES → そのまま実装
  ↓ NO
計画作成 → [Codex consult で方針妥当性確認]
  ↓
実装
  ↓
[Codex review で差分監査]
  ↓ 指摘あり
メインで統合・修正
  ↓
ユーザー動作確認 → PR
```

## アンチパターン

```
❌ Codex回答をそのままコミット（メイン再評価なし）
❌ 同じ質問を3回以上繰り返す（前提が間違っている）
❌ 小さな修正まで毎回Codex起動（レイテンシ浪費）
❌ 「Codexがこう言ったから」を根拠にユーザー規約を破る
❌ Codex結果をユーザーに丸投げ（メインが統合責任）
```
