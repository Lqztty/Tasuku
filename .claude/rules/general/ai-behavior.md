# AI行動制約

> **参照**: このファイルは全エージェント共通の行動規範です。
> - 技術詳細 → `ai-instructions.md`
> - 作業ルール → `work-rules.md`
> - DDD詳細 → `backend/laravel-conventions.md`

## 最重要制約

| 原則 | 説明 |
|------|------|
| **DDD厳守** | Domain/Application/Infrastructure 3層に必ず従う |
| **要求のみ実装** | ユーザーが明示した機能のみ。余計な追加機能禁止 |
| **推測禁止** | 不明な点は必ず質問。仮定・推測は一切禁止 |
| **イミュータビリティ** | 既存オブジェクト変更禁止。常に新規作成 |
| **既存パターン遵守** | 新規要素（色、UI、トークン等）の発明禁止 |
| **主担当責任** | メインエージェントが文脈把握・方針決定・最終統合を担う |

DDD 3層詳細 → `backend/laravel-conventions.md`

## 不確実性への対処

```
❌ 推測して実装
❌ 「おそらく〜だと思われます」
✅ 1〜3個の的確な質問でユーザーに確認
✅ 「〜について確認させてください」
```

低リスクで局所的な作業は、明示した前提のもとで進めてよい。
高リスク・不可逆・仕様影響が大きい場合のみ質問や承認を優先する。

## イミュータビリティ

```typescript
// ✅ 正しい
return { ...user, name };

// ❌ 禁止
user.name = name;
return user;
```

**例外**: Zustand Immer（ドラフト状態のみ）

Docker実行・フォーマッター → `code-style.md`

## コードレビュー

- 出力前に最大3ラウンドのセルフレビュー実施
- 完璧なら早期停止可
- 非自明な変更は、`/code-review` による批判的セカンドオピニオンを優先

## サブエージェント運用

```
❌ 形式的な委任（小さな単発作業まで毎回委任）
❌ 問題理解前の丸投げ
❌ 結果を無検証で採用
✅ 先にメインが要件と論点を整理
✅ 係に渡すのは広い検索・並行作業・別の目のレビューだけ (`work-rules.md`)
✅ 委任時は対象ファイル、期待成果、制約を明記し、結論だけ返させる
✅ 返却後にメインが統合責任を持つ
```

## スキル起動

```
✅ ユーザーがスキル名を言わなくても、意図が一致したら自動起動
✅ 品質・速度・安全性が上がるならスキルを優先
❌ 「明示指示がないから使わない」という待ち姿勢
```

## 自己修復

```
✅ 用語が揺れたら canonical なユビキタス言語へ戻す
✅ ドメイン知識と矛盾した実装を見つけたら、その場で修正する
✅ 共通化できる UI を feature 内に複製したら、その場で Components/ へ寄せる
❌ 「今回は通す」「後で直す」を常態化しない
```

修復対象:
- ユビキタス言語との不一致
- Domain/Application/Infrastructure の責務ずれ
- 共通コンポーネントの重複
- deprecated 用語や独自言い換えの混入

## 承認境界

```
✅ 小規模変更は承認なしで実装してよい
✅ 中規模以上は計画またはスコープ要約後に承認を取る
❌ すべての変更で承認待ち
❌ 承認が必要な変更を無断で進める
```

小規模変更の条件 → `work-rules.md`「小規模変更の定義」参照

言語設定 → `CLAUDE.md`参照

## 禁止事項

```
❌ ユーザー要求外の追加機能
❌ 新規UI要素の発明（色、影、トークン、アニメーション）
❌ 曖昧な指示への推測
❌ 既存オブジェクトの変更
❌ Controller内でのビジネスロジック
❌ Docker外でのコマンド実行
```
